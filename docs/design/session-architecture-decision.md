# Current authentication architecture decision

**Status:** Approved and implemented authentication baseline; feature acceptance review pending.

Spring Security with Spring Session JDBC and PostgreSQL supersedes the historical RS256 JWT/stateless plan. Java 21, Boot 3.5.16, Angular 20, Flyway, the modular monolith and same-origin `/api/v1` remain unchanged. There is one backend deployment unit, with no API Gateway, OAuth provider, Redis or new service.

Authentication owns canonical account lookup, PBKDF2-HMAC-SHA256, operational provisioning and lifecycle controllers; security consumes narrow account/activity interfaces, validates persisted contexts and enforces authorization. Authentication accounts remain separate from banking accounts. No business controller or future business allowlist is introduced by this feature.

The versioned `{pbkdf2-sha256-v1}` encoder uses random 16-byte salts, 600,000 iterations and a 256-bit key. Provisioning/replacement accepts exact well-formed 8–128 Unicode code points, preserving spaces and input beyond BCrypt's byte limit; login accepts non-empty well-formed input up to 128 without applying the creation minimum, preserving existing-hash compatibility. Assessment-hardware medians were 573.409 ms encode / 571.946 ms verify, with two warm-ups and five samples; deployment capacity/rate controls remain hardening work. Password/hash output is excluded from APIs/logs. Operational account provisioning uses the explicit non-web masked-console command, without an ADMIN role, public registration, password CLI/environment inputs or startup users. See [provisioning](../operations/account-provisioning.md).

GET `/api/v1/auth/csrf` materializes a JDBC anonymous token and returns masked material for `X-CSRF-TOKEN`. POST `/auth/login` accepts only email/password; GET `/auth/me` returns only id/email/current role; POST `/auth/logout` returns null after synchronous deletion. All paths use the established JSON envelope/no-store/correlation conventions, documented in [API contract](api-contract.md). CSRF precedes unsafe behavior, including login/logout, with generic 403/1010. Unknown/wrong/disabled credentials share 401; detected store failures before commitment return 503/3002.

SESSION is opaque, host-only, HttpOnly, SameSite=Lax, path `/api/v1`, browser-session lifetime and Secure=true by default. Only explicit `local` permits Secure=false for the Angular HTTP proxy workflow; production/local conflicts and insecure production defaults/overrides fail startup. Fixed Secure configuration cannot be downgraded by spoofed forwarding headers. Production operators must select the production profile and provide HTTPS through their trusted deployment boundary.

Spring Session 3.5.7 uses IMMEDIATE flush, ON_SET_ATTRIBUTE and a 1,800-second interval. Explicit supported fixation/CSRF strategies run at login, context attribute persistence flushes the changed identifier, and a row-locked account recheck commits activation metadata before success. JDBC framework persistence and metadata activation are separate transactions; partial failures are fail-closed rather than falsely claimed atomic rollback. Logout deletes one session; account changes increment auth_version and revoke all older sessions across instances. Re-enabling never revives old versions.

The authoritative strict idle deadline uses auth_session_activity. Every protected request validates current account, supported role, captured version and PostgreSQL-time expiry before authorization. A marked eligible MVC handler renews at admission using the request's public framework access timestamp and guarded monotonic SQL, even if later validation/handling fails. Only identity currently qualifies. Health/bootstrap/logout/unmatched/rejected/background requests never renew authentication, and Angular never polls identity. Equality at 30 minutes expires independent of row cleanup. Synchronize backend/database clocks; no unapproved skew allowance is introduced.

Flyway V2–V4 add account/version/canonical-email constraints, pinned Spring Session tables and activity metadata. Historical V1 and foundation specifications/evidence stay unchanged. Configurable minute cleanup deletes expired parents and cascades their attributes/activity; active anonymous CSRF sessions remain. Compatible instances share schema, serialization and cookie settings. Java serialization assumes controlled DB access and compatible release rollout; incompatible principal serialization needs explicit invalidation planning.

Angular's initializer bootstraps then resolves identity before protected content; signal stores contain only non-secret identity/UI and in-memory CSRF material. Functional guards return role-specific UrlTrees and local allowlisted return destinations. No JWT, bearer header, cookie reads, localStorage/sessionStorage authentication or automatic unsafe replay. 401 clears identity/private views; 403/503 remain distinct. Confirmed transitions survive later token-refresh failure, while transport-ambiguous logout hides protected content and offers deliberate bootstrap/retry.

A normally ordered outer availability filter precedes Spring Session. Required login activation, logout deletion and handler admission persistence complete before success. Actual fault tests verify pre-commit save failures return generic 503 with cookies withheld; a post-commit finalization fault can terminate the response body after headers, and is an unconfirmed transport outcome. Safe operational logs report commitment; no custom buffering, private framework flush hooks or retroactive HTTP rewrite promise is used. Health GETs remain session-independent; readiness depends on DB while liveness does not. See [operations](../operations/authentication.md) and feature acceptance evidence for exact executed scenarios.

Ordinary redacted outcome logs are not crash-atomic with database commits. Restricted log retention, trusted OS/database administration and secure credential delivery are operational prerequisites. Stronger durable audit, abuse controls, deployment infrastructure and capacity work remain deferred; assessment verification does not imply production readiness. Unrelated pagination, idempotency, ownership, ETag/If-Match and terminal assignment decisions are preserved.
